## 摘要
世界行动模型（WAMs）联合预测未来行动与环境演化。在每次推理时，WAM会生成一段行动块，机器人在重新规划前执行固定长度的前缀。我们认为，这种固定执行时域与执行动态不匹配：行动块的可靠性在不同任务阶段有所变化，因此何时重新规划应取决于累积执行的结果，而非步数计数。我们提出TempoWAM（通过在线监控进度来把握执行时机），一种用于WAM的轻量级即插即用执行方案。循环进度监控器首先根据当前观测、任务指令、剩余行动和执行历史估计任务进度；自适应执行协议随后评估该行动块是否正在推进任务，以决定是否需要重新规划。为了弥合训练与部署之间的差距，该协议通过具有在线自适应能力的任务相关校准因子进行校准。在LIBERO、RoboTwin和真实世界任务上的实验表明，TempoWAM持续改善了WAM执行的效率-成功权衡。在真实机器人上，它在简单任务上将WAM推理减少26.9%同时保持成功率，并在困难任务上将成功率提升13.3个百分点。

## Abstract
World Action Models (WAMs) jointly predict future actions and the evolution of the environment. At each inference, a WAM generates a chunk of actions and the robot executes a fixed prefix before replanning. We argue that this fixed execution horizon is poorly matched to execution dynamics: the chunk reliability varies across task stages, so when to replan depends on the result of accumulated execution, not on the step counts. We propose TempoWAM (Timing Execution by Monitoring Progress Online), a lightweight plug-and-play execution scheme for WAMs. A Recurrent Progress Monitor first estimates task progress from the current observation, task instruction, remaining actions, and execution history; and an Adaptive Execution Protocol then evaluates whether the chunk is advancing the task to decide if replanning is needed. To bridge the training-deployment gap, the protocol is calibrated by a task-dependent calibration factor with online adaptation. Experiments on LIBERO, RoboTwin, and real-world tasks show that TempoWAM consistently improves the efficiency-success trade-off of WAM execution. On real robots, it reduces WAM inferences by 26.9% on easy tasks while maintaining success, and improves success by 13.3 points on difficult tasks.

# 论文总结：TempoWAM——世界行动模型的自适应执行方案

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：世界行动模型（WAM）能够同时预测未来动作与环境演化，在机器人操作中日益重要。每次推理时，WAM 生成一段动作块（action chunk），机器人通常执行固定长度的前缀后再重新规划。
- **核心问题**：固定执行时域（fixed execution horizon）与任务实际执行动态不匹配——动作块的可靠性并非全程一致：在简单任务阶段，一个块可以长期保持准确；而在困难阶段，误差快速累积，仅几步后便失效。因此，何时重新规划不应由固定步数决定，而应取决于累积执行状态和任务进展。
- **深层含义**：现有自适应执行方法多依赖动作熵、预测一致性、注意力权重等代理指标，这些指标没有直接衡量“任务是否在推进”，导致判断可能误导。对于 WAM 而言，执行决策应基于“剩余动作是否仍能推进任务”，而非块表面是否合理。
- **目标**：提出一种轻量级、即插即用的执行层方案，使重规划时机随任务状态自适应调整，提升效率与成功率的权衡。

## 2. 方法论：核心思想、关键技术细节与流程

### 核心思想
- 用“任务进度”作为执行决策的自然判据，由轻量级监控器在线估计进度，并据此决定继续执行当前动作块还是丢弃并重新规划。

### 方法组成
- **TempoWAM = Recurrent Progress Monitor (RPM) + Adaptive Execution Protocol (AEP)**
  - **RPM**：估计如果执行候选动作前缀后能达到的任务进度。输入包括当前观测、任务指令、剩余动作候选、候选前缀长度、上一进度估计和史信息。
    - 观测编码：复用 WAM 冻结视觉骨干，投影到监控空间。
    - 动作编码：递归编码候选前缀，拼接长度嵌入。
    - 历史循环：将上一进度估计注入 GRU 状态。
    - 输出：进度值 \(v_t \in [0,1]\)。
  - **AEP**：比较“当前进度率”（\(\rho_{\text{cur}}\)）与“所需进度率”（\(\rho_{\text{need}}\)）的比值，若低于阈值则触发重规划。
    - 公式（简化）：\(\tilde{r}_t = \rho_{\text{cur}} / \rho_{\text{need}}\)，校准后 \(r_t = \tilde{r}_t / \kappa_{\text{final}}\)，当 \(r_t < 1\) 时重新规划。
- **校准机制**：
  - 离线：从任务演示中拟合每任务校准因子 \(\kappa_{\text{task}}\)（最小二乘+中位数聚合）。
  - 在线：episode 内 EMA 更新 \(\kappa\)；episode 间根据近期成功率调整缩放因子 \(\delta'\)，引导目标成功率。
- **训练目标**：在 WAM 相同的演示轨迹上训练，监督标签为归一化时间进度 \(u/T\)。损失包含：
  - 进度预测的 BCE 损失；
  - 平滑正则项（抑制进度波动）；
  - 历史一致性正则项（对观测掩码，增强鲁棒性）。

## 6. 主要结论与发现

- **核心结论**：固定执行时域次优；TempoWAM 通过进度感知的自适应执行，能持续改善 WAM 的效率-成功权衡。
- **仿真结果**：
  - RoboTwin 短时域任务：在保持或提升成功率的同时减少 WAM 调用（如 click_bell 从 3.00 降至 2.04 次调用，成功率 100%）。
  - RoboTwin 长时域任务：成功率提升（清洁环境 86.93% → 88.47%；随机化 84.47% → 85.33%），同时减少执行步数。
  - LIBERO：平均调用从 14.88 降至 12.46，成功率保持 97.25%。
- **真实机器人**：
  - 简单任务 take drinks：成功率不变（90%），调用减少 26.9%（32.7 → 23.9）；
  - 困难任务 pack hand cream：成功率从 50% 提升至 63.3%。
- **跨骨干**：TempoWAM 无需重新训练即可提升 Motus 成功率（如 move_can_pot 提升 59 个百分点）。
- **行为分析**：在线 EMA 能吸收监控器在困难阶段的乐观偏差，自动收紧阈值；成功门控的 δ' 会自动匹配任务难度，无需人工调参。
- **时间标签诊断**：时间型进度标签仅在观测序列“进度单调且无别名”时有效；镜像序列导致自相矛盾监督，监控器无法学习，证明其估计依赖于视觉状态而非步数计数。

## 7. 优点

- **即插即用**：完全在执行层工作，无需修改或重新训练主干 WAM，可轻松迁移至不同 WAM。
- **直接以任务进度为判据**：避免使用熵、一致性等间接代理指标，更贴合执行本质。
- **轻量高效**：RPM 仅 2.27M 参数（约为骨干的 0.038%），单次决策成本约为一次 WAM 调用的 3.54%（复用视觉特征时仅 0.34%）。
- **双时间尺度自适应校准**：有效弥合训练-部署分布差距，且能随任务难度自动调整。
- **实验设计有深度**：不仅报告性能，还深入分析校准行为、失败模式和时间标签有效性，为后续研究提供洞见。

## 8. 不足与局限

- **对时间标签的依赖**：进度监督基于线性时间归一化，仅适用于单调非重复任务；周期性或对称性任务（如来回重复倒水）会失效，需未来引入阶段分解或语义进度。
- **校准依赖任务演示**：离线 \(\kappa_{\text{task}}\) 需要演示数据；无演示时只能从 \(\kappa=1\) 开始在线微调，可能在前几个 episode 性能不稳定。
- **真实实验规模有限**：仅 3 个真实任务、每任务 30 次试验，统计功效偏低；任务类别也未覆盖复杂长程操作。
- **对比基线不够广泛**：未与基于未来验证或强化学习学习时域的方法对比；AAC 的成本计数方式可能略微有利于 TempoWAM。
- **超参数敏感性**：\(\lambda, \eta, s^*, \delta'\) 取值范围等需要预设，不同任务可能需要调整。
- **可迁移性限制**：实验仅覆盖两个 WAM 骨干（FastWAM、Motus）；若换成非常规架构（不共享观测编码），RPM 需要重新适配。
