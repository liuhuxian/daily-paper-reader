## 摘要
训练API调用的大语言模型（LLM）代理需要大量高质量的执行轨迹。然而，大规模收集此类数据通常需要完全实现的环境，包括可执行的API和预填充的真实后端数据库，这成为了可扩展性的主要瓶颈。为了克服这一点，我们提出了一种无环境的合成数据生成方法，利用LLM作为即时数字世界模型。仅给定API规范，我们的方法生成模仿代理与有状态环境之间交互的轨迹。具体来说，LLM首先生成可使用提供的API解决的多样化任务。然后，一个教师代理迭代地解决每个任务，同时一个LLM模拟器根据任务上下文和模拟历史生成连贯的合成API响应。最后，一个LLM评判者过滤轨迹以确保生成数据集的质量。我们在具有挑战性的AppWorld和OfficeBench基准上评估我们的方法，这些基准包括信息检索和状态改变任务。在我们的合成数据上微调模型取得了显著的性能提升，证明无需任何可执行环境即可生成用于API调用代理的有效监督信号。我们的结果表明，基于LLM的API模拟是一种实用且可扩展的解决方案，可用于跨不同API生态系统训练代理。

## Abstract
Training API-calling large language model (LLM) agents demands massive amounts of high-quality trajectories. However, collecting such data at scale typically requires fully implemented environments with executable APIs and realistic, pre-populated backend databases, creating a major bottleneck for scalability. To overcome this, we propose an environment-free synthetic data generation approach that leverages LLMs as on-the-fly digital world models. Given only API specifications, our method generates trajectories mimicking interactions between an agent and a stateful environment. Specifically, an LLM first generates diverse tasks solvable with the provided APIs. A teacher agent then iteratively solves each task while an LLM simulator generates coherent synthetic API responses conditioned on the task context and simulation history. Finally, an LLM judge filters the trajectories to ensure the quality of the resulting dataset. We evaluate our approach on the challenging AppWorld and OfficeBench benchmarks, which include both information-retrieval and state-changing tasks. Fine-tuning models on our synthetic data yields significant performance gains, demonstrating that effective supervision for API-calling agents can be generated without any executable environment. Our results establish LLM-based API simulation as a practical, scalable solution for training agents across diverse API ecosystems.

- **核心猜想**：现代LLM预训练了海量世界知识，可以作为动态数字世界模型——仅凭API规格，就能在给定任务上下文和交互历史后，生成连贯、有状态的模拟API响应。
- **研究目标**：提出一种**完全环境无关**的合成数据生成方法，将轨迹生成简化为“规格输入→数据输出”的轻量级流水线，从而大幅降低扩展成本。

## 2. 方法论

### 2.1 核心思想：ESAT流水线
ESAT（Environment-Free Synthetic Agentic Trajectory）由三个阶段组成，仅需输入API规格（名称、参数、响应模式）。

### 2.2 关键技术细节

#### 阶段一：任务合成（Task Synthesis）
- **桶式生成**：按难度（easy/medium/hard）、动作类型（read/write/mixed）、任务焦点（constraint satisfaction/derivation/iteration/open）、应用数（1-3）、每应用API数等构建配置桶，随机排序后逐个生成任务。
- **逆频率采样**：记录每个应用和API已被使用的次数，采样时优先选择使用少的应用，并指示生成器聚焦低频API，保证覆盖均匀。
- **任务评判与改写**：生成的任务由LLM评判是否可解、符合配置；通过后由LLM将冗长的步骤式指令改写为简洁的意图式用户请求，再经最终评判保留。

#### 阶段二：轨迹合成（Trajectory Synthesis）
- **教师Agent**（GLM-5.1-FP8）迭代调用API解决每个任务。
- **API模拟器**（同样使用GLM-5.1-FP8）根据以下上下文生成合成响应：
  - API规格、调用参数、任务描述
  - 同应用的历史调用-响应对（限制上下文长度）
  - 虚拟用户信息（姓名、邮箱、电话）
  - 当前日期时间
- **模拟器规则**：
  - 数据一致性：跨调用保持状态（如已创建的歌曲仍在）
  - 数据多样性：结果混合相关/不相关项目
  - 数据真实性：符合字段约束（数值范围、唯一ID等）
  - 模式合规：严格符合响应模式
- **质量检查**：确定性参数验证（类型、缺失、约束）→ 模式验证 → LLM语义判官（仅对读API）→ 失败重试（有预算限制）。

#### 阶段三：轨迹过滤（Trajectory Filtering）
- 使用Gemini-3.1-Pro作为轨迹级评判，评估正确性、完整性、冗余，仅保留多数为通过的轨迹。

- **OfficeBench**：8个应用，20个API；评估2-app（26任务）和3-app（46任务）场景。

## 7. 优点

- **高度可扩展**：仅需API规格，无需实现环境或填充后端数据库，可无缝迁移到任意API生态。
- **状态模拟能力**：模拟器维护跨调用的状态一致性，支持写API，支持多步复杂交互，超越了简单工具调用数据集。
- **覆盖均衡**：采用桶式生成和逆频率采样，确保任务难度、焦点、应用、API的多样性覆盖。
- **多级质量控制**：任务评判、参数校验、模式验证、语义判官、轨迹过滤等多种机制保证数据质量。
- **实证充分**：在多个模型家族、多种数据源、多种指标下验证，并进行了人工和自动外部验证。
- **知识蒸馏有效**：证明了环境无关的合成数据可用于将大模型能力转移到小模型。

## 8. 不足与局限

- **模拟器长输出能力有限**：超过2K tokens的响应失败率较高（≥23%），可能限制需要长列表或长文本的任务。
- **分布偏差**：多应用任务（2-app、3-app）在生成轨迹中占比显著小于单应用任务，可能影响跨应用泛化。
- **基准覆盖有限**：仅验证了AppWorld和OfficeBench，未在更多真实世界API（如云服务、电商、社交媒体）上测试。
- **同源偏差**：教师代理和模拟器使用同一模型（GLM-5.1-FP8），可能引入模式偏见；且评判模型（Gemini）与生成模型不同，但未详细分析偏差影响。
- **成本未量化**：生成大量轨迹（如9K条）所需要的LLM API调用次数和费用未讨论，实际部署成本可能较高。
- **缺少错误鲁棒性分析**：当模拟器产生矛盾或错误状态时，轨迹质量如何受影响未深入分析。
- **与真实环境数据增强方法的对比不充分**：仅对比了AWT和现有合成数据集，未与基于真实环境但采用数据增强（如噪声注入、重组）的方法比较。
